# GGU-CASTLE FC

SOOP 스트리머 감독 × 시청자 축구선수 성장형 웹게임

최종 통합 기획서 · 제품/게임 규칙/운영/기술/데이터/ML
문서 버전 1.2 | 작성일 2026-11-05 | 상태: 구현 전 설계안

본 문서는 기존 대화에서 합의된 주요 방향을 통합한 초기 개발 기준안이다. 게임 수치와 일정은 플레이테스트를 통해 조정하며, SOOP의 외부 데이터 사용 권한은 별도 확인 전까지 확정 기능으로 간주하지 않는다.

> **v1.1 변경 요약** — 경기를 **매일 17:00 KST 고정 킥오프**로 바꾸고, 모든 마감을 절대 시각으로 정했다. 라인업 확정 16:30(킥오프 30분 전), 승부예측 마감 16:50(10분 전), 로스터 이동은 마감 없음(단 잠긴 라인업은 그날 경기에 그대로 쓴다). 경기는 실시간 관전 또는 종료 직후 리플레이로 본다. 매일 경기로 바뀌면서 v1.0 컨디션 수식이 유지되지 않아 컨디션 수치를 재튜닝해 확정했다. 변경된 곳은 본문에 **[v1.1]** 로 표시했고, 전체 목록은 문서 끝 «변경 이력»에 있다.

> **v1.2 변경 요약** — 시청자(선수)와 스트리머(감독)의 화면 구성을 나눴다(1.4). 로스터 관리는 라인업과 분리된 **이적 시장(경매장)** 화면으로 독립시켰고, 오퍼는 금전이 아닌 계약 조건으로 경쟁한다(5.3). 시청자는 **구단 목록에서 원하는 스트리머 구단의 모집 슬롯에 자신을 오퍼**하고(주 방식), 자유계약 시장에 자신을 올려 감독 오퍼를 받을 수도 있다(보조, 5.3). **로그인 후 역할(선수/감독)을 정하고, 감독은 SOOP 방송국 확인과 운영자 승인을 거친다(1.5).** **스토어**에서 무상 포인트로 꾸미기 아이템을 구매하고, 거래소에서 유저 간에 거래한다(7.2). 거래소는 12장의 보류 항목 "거래형 포인트"를 일부 여는 결정이라 가드레일과 법률 검토를 붙였다. 변경 위치는 **[v1.2]** 로 표시했다.

## Executive Summary

시청자가 자신을 하나의 축구선수로 등록·육성하고, 스트리머가 구단 감독으로 영입·방출·선발·전술을 수행한다. 매일 웹 미니게임으로 성장하고 **[v1.1] 매일 17:00 리그 경기**에서 자동 시뮬레이션 경기를 치르며, SOOP 시청·후원 기록은 선택적 성장 재화에 반영한다. 장기적으로 경기 로그 기반 선수 가치 예측·훈련 추천·전술 추천 AI를 개발한다.

| 항목 | 초기 결정안 |
|---|---|
| 플랫폼 | 반응형 웹(Next.js) + Unity 2D Web 빌드 + API 서버 |
| 참여자 | SOOP 시청자=선수 / 스트리머=감독 |
| 첫 경기 규격 | 5 대 5 자동 시뮬레이션; 추후 11 대 11 |

| **[v1.1] 경기 시청** | **실시간 시뮬레이션 관전 또는 종료 직후 리플레이** |
| 기본 능력치 | 체력·스피드·슛·피지컬·골키퍼 능력; 컨디션은 별도 상태값 |

### 성공 기준

시청자가 3분 이내 첫 훈련을 마치고, 방송을 보지 않는 날에도 성장하며, 스트리머는 **[v1.1] 매일 17:00 경기를 방송 루틴(라인업 공개 → 예측 → 실시간 관전)으로** 운영할 수 있는가를 가장 먼저 검증한다.

## 1. 제품 목표 및 사용자 역할

### 1.1 디자인 원칙

- 브라우저 우선: 설치 없이 PC·모바일에서 플레이, 저사양/방송 동시 시청 환경 고려.
- 저부담 참여: 미니게임 1판 20~90초, 하루 보상 플레이 4회 이내, 쉬운 클릭·터치 조작.
- 장기 성장: 영구 능력치와 단기 컨디션, 시즌 목표 및 팀 관계 기록을 분리.
- 공정성: 별풍선은 필수 성장 수단이 아니며 비후원자에게도 동일한 최고 능력치 상한 도달 경로 제공.
- 서버 권한: 경기 결과·보상·출전·이적은 서버 확정; 클라이언트 점수는 검증 대상.
- **[v1.1] 고정 시각: 모든 경기와 마감은 KST 절대 시각으로 고정한다. 참가자가 "언제까지 무엇을 해야 하는지"를 외울 수 있어야 하고, 스트리머가 방송 일정에 넣을 수 있어야 한다.**

### 1.3 주요 사용자 흐름

1. SOOP 또는 게임 자체 계정으로 로그인 → **[v1.2] 역할 선택(선수/감독, 1.5)** → 선수 생성(닉네임·포지션·외형) 또는 감독 인증·승인.
2. 스트리머 팀에 입단 지원 → 감독 승인 → 계약 상태 ACTIVE.
3. 하루 미니게임 최대 4판으로 XP 획득 → 원하는 능력치 성장.

### **[v1.2] 1.5 로그인과 역할 결정**

역할(선수/감독)은 로그인 후 한 번 정하고, 서버가 계정에 저장한다. 화면 구성(1.4)·API 권한·내비는 모두 이 값으로 갈린다. 클라이언트는 받은 역할을 표시만 하고 판단하지 않는다.

| 항목 | 규칙 |
|---|---|
| 로그인 수단 | SOOP 계정(OAuth, 권장) 또는 게임 자체 계정(이메일). SOOP 앱 승인 전에는 자체 계정만 연다(4.2) |
| 비로그인 | 랜딩·리그 순위·경기 관전/리플레이 열람만. 훈련·오퍼·예측·스토어·이적 시장은 로그인 필요 |
| 첫 로그인 | 역할 선택 화면으로 이동. 고르기 전에는 비로그인과 같은 범위만 쓸 수 있다 |
| 선수(시청자) | 바로 확정 → 선수 생성. 자체 계정도 가능 |
| 감독(스트리머) | ① SOOP 계정 로그인 필수 ② SOOP 방송국 본인 확인(공식 API로 방송국 ID 조회) ③ 리그 운영자 승인(구단 수 상한·대진 편성 때문). 승인 전 상태는 "감독 승인 대기"이며 관전만 가능 |
| 1계정 1역할 | 감독 계정은 선수를 만들 수 없고, 선수 계정은 구단을 만들 수 없다(1.2 "한 사람 1 선수") |
| 역할 변경 | 시즌 사이에만, 운영자 처리. 선수→감독 전환 시 선수는 은퇴 처리(능력치 기록 보존), 감독→선수 전환 시 구단은 운영자가 인계·해산 |
| 권한 적용 | 로그인 토큰에 role 클레임, 모든 API가 RBAC로 검사(8.2). 화면 분기는 같은 값으로 |

|---|---|---|---|
| 컨디션 C | 0~100 | 현재 경기 준비 상태; 성과 배율·부상 위험 | 회복/휴식(영구 훈련 불가) |

## 3. 미니게임 공통 규칙

### 3.1 플레이·보상 제한

| 항목 | 기본 규칙 |
|---|---|
| 게임 인터페이스 | Unity 2D, 클릭/터치 1~2종 입력, 2D UI/스프라이트 |
| 플레이 시간 | 1판 20~90초; 중도 종료 시 보상 없음 |
| 일일 보상 횟수 | 하루 첫 4판만 XP 지급, 이후 기록/연습만 허용 |
| 1판 XP | 완료 8 XP + 성과 보너스 0~4 XP; 실패 시 완료 XP 4 |
| 동일 능력치 XP 제한 | 1일 해당 능력치 최대 24 XP; 다른 능력치로 분산 유도 |
| 일일 기준 | KST 00:00 초기화; 레이스 조건과 서버 시각 검증 |
| 훈련 성장 | 능력치 s→s+1에 필요한 XP: ceil(10+1.5×max(0,s−40)) |
| 훈련 상한 | 기본 각 능력치 70; 1차 돌파 후 85; 2차 돌파 후 100 |
| **[v1.1] 경기 반영 시점** | **16:30 라인업 잠금 시점의 능력치를 그날 경기에 쓴다. 16:30 이후 훈련으로 오른 능력치는 다음 날 경기부터 반영** |

훈련 점수와 승부차기 성과는 게임 능력치에 관계없이 동일 난이도 기본 규칙으로 평가한다. 높은 능력치가 미니게임 XP까지 더 쉽게 얻는 양의 피드백을 방지하기 위함이다. 각 게임은 완료 보상 비중을 높여 기기 반응속도 격차를 완화한다.

### 3.2 미니게임별 정밀 규칙

**A. 압박 탈출(지뢰찾기 변형)** — 목적: 압박 구역을 피하면서 안전한 전진 칸 10개 확보. 6×6 그리드에 압박 칸 5개가 무작위 배치된다. 최초 클릭은 안전하며, 공개된 숫자는 주변 8칸의 압박 수. 60초 제한, 폭탄 칸을 누르면 즉시 실패한다. 우클릭/길게 누르기로 깃발을 표시하되 깃발 자체는 점수에 영향을 주지 않는다. 완료 시 피지컬 XP 80%, 스피드 XP 20%; 40초 내 완료 +2 XP, 오표시 0회 +2 XP.

**B. 득점 찬스 퍼즐(사과 게임 변형)** — 목적: 숫자 공을 합계 10으로 묶어 찬스를 만든다. 5×5 격자에 1~9 숫자를 표시하고 마우스/손가락으로 직사각형 선택. 선택한 칸 합이 정확히 10이면 제거·즉시 재배치. 45초 동안 4개 조합 달성 시 완료, 6개/8개 달성 시 추가 +2/+4 XP. 서버가 생성한 난수 시드·유효한 조합을 검증한다. 슛 XP 80%, 체력 XP 20%.

**C. 승부차기(공격/골키퍼)** — 공격: 좌/중/우 슛 방향 선택 + 약/중/강 파워 선택 후 5번 차기. 골키퍼: 상대 슛 애니메이션을 보고 좌/중/우 다이빙을 5번 선택. 한 라운드 60초 이내, 방향·파워 판정과 세이브 결과는 서버 시드 또는 판정 테이블로 결정한다. 5회 진행 완료 시 XP 8, 성공 3회 이상 +2, 5회 성공 +4(중복 대신 최고 보너스 적용). 공격은 슛 100%, 수비는 GK 100%.

**D. 스프린트 스타트(반응 훈련)** — 3개의 예고등 이후 1~3초 랜덤 지연, 녹색 신호 시 클릭. 총 5번 반복, 시작 전 클릭은 해당 회차 실패. 유효 반응시간의 중앙값으로 +0~4 XP 산출(권장 초기 기준 300ms 이내 +4, 450ms 이내 +2). 스피드 100%. 터치 기기와 키보드의 환경 차이는 장치 그룹별 테스트 후 보정한다.

**E. 어깨싸움(밸런스 훈련)** — 좌우로 이동하는 막대가 중앙 목표 구간에 들어왔을 때 클릭/터치. 총 5회, 매 라운드 막대 속도와 목표 구역 위치를 변경. 성공 3회 이상 +2, 5회 성공 +4 XP. 피지컬 100%. 25~40초 내 종료.

**F. 페이스 유지(체력 리듬)** — 30초 동안 20번 표시되는 박자에 맞춰 화면을 1회 터치. 허용 오차 ±250ms; 미리 연타해도 1회씩만 수용. 적중률 60% 이상 +2, 85% 이상 +4 XP. 체력 100%. 소리를 듣지 못해도 시각 신호로 동일하게 플레이 가능.

## 4. 한계돌파와 SOOP 연동

### 4.1 한계돌파(최고 능력치 잠금 해제)

개별 능력치가 현재 상한에 도달하면 추가 XP가 적립되더라도 실제 수치는 증가하지 않는다. 성장 가능한 상한을 확장하는 행위를 한계돌파라고 정의한다. 70→85: 돌파 증표 8개, 85→100: 증표 20개. 상한만 해제하며 능력치는 이후 미니게임 XP로 계속 키워야 한다.

| 돌파 증표 공급처 | 주간 최대 | 세부 규칙 |
|---|---|---|
| 게임·팀 활동 | 8개 | 경기 출전/대기 2, 팀 공동 미션 4, 일일 임무 달성 2 **[v1.1] 경기가 매일 열려도 출전/대기 몫은 주 2개로 유지** |
| 시청 활동 | 2개 | 검증된 방송 시청 또는 대체 출석 미션; 외부 조회 미승인 시 대체 경로 우선 |
| 별풍선 후원 | 1개 | 승인된 실시간 후원 이벤트 확인 시 소량 지급; 유료 필수 아님 |
| 합산 상한 | 10개 | 모든 공급처 합산 주 10개; 게임 활동만으로도 시간 경과에 따라 돌파 가능 |

후원 경로는 주 10개 한도 중 최대 1개분만 기여한다. 후원자의 최고 성장 상한·최종 능력치는 무료 사용자와 동일하며, 후원 기록은 팀 소속을 바꿔도 적립된 증표를 회수하지 않는다. 정확한 별풍선 전환량은 정책 검토 후 결정한다.

### 4.2 외부 연동 상태

| 데이터 | 기술적 근거 | 제품 의존성 |
|---|---|---|
| SOOP 계정 인증 | 공식 Open API 인증 흐름 존재 | 앱 등록/동의/권한 승인 필요 |
| 별풍선 | 공식 Chat SDK 연동 서비스 사례 확인 | 스트리머 승인·Scope·이벤트 검증 필수 |
| 시청 시간 | 월별 리캡 등 본인 시청 통계 조회 사례 | 게임 서버의 정식 조회 권한 아직 미확인 |
| SOOPSCOPE | 외부 공개 후원 통계 사이트 | 제휴 API·재사용 허용 미확인; 기본 경로로 사용 금지 |

원칙: 인증되지 않은 스크래핑, 쿠키 추출, 확장 프로그램의 원본 기록 무단 복제는 하지 않는다. 시청 시간 연동이 불가능하면 자체 방송 출석 이벤트 및 게임 활동 미션으로 동일한 보상을 대체한다. 수집 범위·보관 기간·삭제 절차를 사용자에게 고지한다.

## 5. 스트리머 감독/팀 운영

### 5.1 팀 규격과 명단

MVP: 5 대 5(필수 GK 1명, 필드 4명) + 후보 최대 3명으로 총 등록선수 8명. 유저가 부족하면 OVR 45의 고정 NPC로 보충하지만 NPC는 성장·리워드를 얻지 않는다. 이후 참가자 수에 따라 정식 11 대 11로 확장한다.

| 감독 기능 | 상세 동작 |
|---|---|
| 지원서 관리 | 포지션·OVR·활동 요약 확인 후 수락/거절 |
| 영입 | 자유계약 선수 제안 → 선수 수락 → 이적 완료 |
| 방출 | 감독 권한으로 자유계약 상태 전환; 개인 레벨과 능력치는 유지 |
| 트레이드 | 두 감독 제안 + 양 선수 동의 + 운영 정책 검증 필요 |
| 출전 명단 | GK 1명 포함 선발 5명 및 후보 0~3명, 포메이션 설정 |
| 전술 | 공격적/균형/수비적 3종, 경기 중 변경 없는 1차 구현 |
| **[v1.1] 라인업 확정** | **매일 16:30 KST(킥오프 30분 전) 잠금. 미제출·무응답 시 직전 경기 라인업, 없으면 OVR 순 자동 명단 생성. 잠금 후 당일 수정 불가** |
| **[v1.1] 로스터 이동** | **지원 승인·영입·방출·트레이드는 시간 제한 없이 언제든 가능** |
| **[v1.2] 로스터 화면** | **라인업과 분리된 독립 화면(이적 시장). 로스터는 영입·방출·트레이드, 라인업은 출전 편성만 다룬다** |

무단 강제 이적은 허용하지 않는다. 선수의 보유 능력치와 훈련 경험은 팀 이적 후에도 유지하며, 팀워크·감독 신뢰도 같은 관계성 수치만 새 팀에서 다시 형성한다.

#### **[v1.1] 5.2 로스터 이동과 라인업 잠금의 관계**

로스터 이동에는 마감이 없지만, 16:30에 잠긴 라인업은 그날 경기의 유일한 근거다. 서버는 잠금 시점에 라인업 스냅샷(선수·포지션·능력치·컨디션·전술)을 `matches.lineup_snapshot`으로 저장하고, 경기는 스냅샷만 읽는다.

| 상황 | 처리 |
|---|---|
| 16:30 이후 입단·영입된 선수 | 다음 날 경기부터 라인업에 넣을 수 있다 |
| 16:30 이후 방출·이적된 선수가 원 소속팀 라인업에 있음 | 그날 경기는 스냅샷대로 원 소속팀으로 출전, 보상(출전 XP·컨디션 변화)은 선수 본인에게 적용. 새 팀 소속은 다음 날부터 |
| 같은 날 두 팀 라인업에 한 선수가 들어갈 수 있나 | 불가. 새 팀 라인업은 이미 16:30에 잠겨 있어 당일에는 넣을 수 없다 |
| 잠금 직후 라인업 선수가 계정 삭제·제재 | 스냅샷 기준 고정 NPC(OVR 45)로 대체, 감사 로그 기록 |

이적은 언제든 되지만 경기 결과에는 다음 날부터 반영되므로, 경기 직전 영입으로 상대를 노리는 "막판 보강"이 구조적으로 막힌다.

#### **[v1.2] 5.3 이적 시장(경매장)**

이적 시장은 두 방향의 오퍼로 움직인다. **주 방식은 선수가 구단에 "나를 써 달라"고 오퍼하는 것**이고, 구단이 자유계약 선수에게 먼저 오퍼하는 길은 보조로 남긴다. 어느 쪽이든 경매의 긴장감(남은 시간·경쟁 오퍼 수·마감 임박)은 가져오되 **입찰 수단은 돈이나 포인트가 아니라 계약 조건**이다. 무상 포인트를 입찰에 쓰면 포인트가 선수 가치를 사고파는 화폐가 되어 7장 원칙(포인트로 선수 강화 금지)과 12장 보류(거래형 포인트)를 동시에 깨기 때문이다.

##### A. 선수 → 구단 오퍼 (주 방식)

구단의 **모집 슬롯**이 매물(lot)이다. 감독이 공석 포지션별로 슬롯을 열면, 시청자들이 자기 카드를 걸고 오퍼를 낸다. 감독은 경쟁 오퍼 중 하나를 낙찰한다.

| 항목 | 규칙 |
|---|---|
| 슬롯 개설 | 감독이 Roster 화면에서 포지션·역할(선발 / 로테이션 / 후보)을 정해 연다. 동시에 열 수 있는 슬롯 수 = 8 − 현재 로스터 인원 |
| 슬롯 기간 | 개설 후 24시간. 감독은 기간 중 언제든 낙찰해 조기 마감할 수 있다 |
| 오퍼 자격 | 자유계약 선수만. 소속 선수는 트레이드(이적 동의) 흐름을 탄다 |
| 오퍼 내용 | 희망 역할, 포지션, 희망 등번호, 어필 메시지(100자). 선수 카드(OVR·포지션·컨디션·활동일·출전 수·지킨 약속 비율)가 자동 첨부된다 |
| 동시 오퍼 | 선수 1명당 진행 중 오퍼 최대 3건 |
| 공개 정보 | 선수에게: 슬롯의 남은 시간·경쟁 오퍼 수. 다른 선수의 신원은 비공개. 감독에게: 모든 오퍼와 첨부 카드 |
| 낙찰 | 감독이 하나를 고르면 이적 완료. 마감 후 48시간 안에 고르지 않으면 슬롯과 오퍼는 자동 만료 |
| 거절 | 감독은 개별 오퍼를 즉시 거절할 수 있고, 거절된 선수는 같은 슬롯에 다시 오퍼할 수 없다 |

##### B. 구단 → 선수 오퍼 (보조)

자유계약 선수가 자신을 시장에 매물로 올리면, 감독들이 계약 조건으로 오퍼한다. 선수가 고른다.

| 항목 | 규칙 |
|---|---|
| 매물 등록 | 자유계약 선수가 직접 등록(Clubs 화면). 방출된 선수는 자동 등록 여부를 본인이 고른다 |
| 경매 기간 | 등록 후 24시간. 선수는 기간 중 언제든 오퍼를 즉시 수락해 조기 종료할 수 있다 |
| 오퍼 내용 | 역할(선발 보장 / 로테이션 / 후보), 포지션, 주장 지명 여부, 등번호, 메시지(100자) |
| 공개 정보 | 남은 시간, 오퍼 수, 받은 오퍼의 역할 분포(예: 선발 보장 2). 어느 구단이 냈는지는 선수에게만 공개 |
| 감독 제한 | 동시 진행 오퍼 최대 3건, 로스터가 8명이면 오퍼 불가(방출 후 가능) |
| 낙찰 | 마감 시 선수가 받은 오퍼 중 하나를 고른다. 72시간 안에 고르지 않으면 매물은 자동 재등록 없이 종료 |

#### **[v1.2] 5.4 두 방향의 공통 규칙**

| 항목 | 규칙 |
|---|---|
| 확정 | 어느 방향이든 이적이 하나 확정되면 그 선수의 나머지 오퍼(보낸 것·받은 것)는 모두 자동 철회 |
| 로스터 상한 | 8명인 구단은 슬롯을 열 수 없고, 구단 카드의 오퍼 버튼은 "정원 마감"으로 바뀐다 |
| 출전 반영 | 이적 완료가 16:30 이후면 다음 날 경기부터(5.2) |
| 약속 이행 | 오퍼의 역할(선발 보장 등)은 신뢰도 지표로만 기록한다. 이적 후 7일간 실제 선발 비율을 구단과 선수 양쪽 카드에 표시하고 강제하지는 않는다 |
| 역할 검사 | 선수 → 구단 오퍼는 선수 역할만, 슬롯 개설·구단 → 선수 오퍼·낙찰은 감독 역할만(1.5, 8.2) |

## 6. 경기 시뮬레이션, 컨디션 및 부상

### 6.1 경기 구성

한 경기는 서버에서 계산하는 5 대 5 자동 시뮬레이션이다. 2개 하프 × 6차례 공격 기회(양 팀 합계 총 12개 시퀀스)로 구성하며, 포지션별 OVR·전술·현재 컨디션·골키퍼 방어력을 이용해 공격 찬스와 득점 여부를 판정한다. 동일한 입력과 난수 시드에서는 항상 같은 결과가 나오도록 구현한다. 클라이언트 Unity는 계산된 이벤트를 2D 애니메이션으로 재생한다.

#### **[v1.1] 6.2 일일 경기 타임라인**

| 시각 (KST) | 이벤트 | 서버 동작 |
|---|---|---|
| 00:00 | 일일 정산 | 컨디션 회복, 미니게임 보상 횟수 초기화 (3.1, 6.4) |
| 00:00 ~ 16:30 | 라인업 편성 | 감독이 선발·후보·포메이션·전술을 저장(여러 번 수정 가능) |
| 16:30 | **라인업 확정** | 라인업 스냅샷 저장, 미제출 팀 자동 명단, 경기 시드 해시 커밋(`seed_commit`), 승·무·패 확률 p 공개 |
| 16:30 ~ 16:50 | 승부예측 | 시청자 예측 접수(계정당 경기당 1회) |
| 16:50 | **예측 마감** | 예측 잠금 |
| 17:00 | **킥오프** | 스냅샷 + 시드로 경기 전체를 계산해 저장, 이벤트 공개 시각을 배정 |
| 17:00 ~ 약 17:07 | 실시간 관전 | 이벤트를 공개 시각이 지난 것만 순서대로 송출 |
| 경기 종료 직후 | 결과 확정·리플레이 공개 | 시드 원문 공개, 결과·보상·컨디션 반영, 리플레이 무제한 재생 |

시각은 서버 정책 파일(`schedule.kickoff=17:00`, `lineup_lock_offset=30m`, `prediction_close_offset=10m`)로 관리하고, 운영자 변경은 감사 로그를 남긴다. 서버 장애로 킥오프가 늦어지면 같은 스냅샷·시드로 지연 실행하며, 예측과 라인업은 다시 열지 않는다.

#### **[v1.1] 6.3 실시간 관전과 리플레이**

경기 결과는 17:00에 한 번에 계산되지만, 시청자가 결과를 미리 알 수 없도록 이벤트를 시간에 맞춰 공개한다.

- **실시간 관전(LIVE)** — 12개 시퀀스를 시퀀스당 약 30초, 하프타임 1분으로 배치해 17:00~약 17:07에 송출한다. 서버는 `match_events.release_at`이 지난 이벤트만 응답하므로 API를 직접 호출해도 결과를 앞당겨 볼 수 없다. Unity 클라이언트는 받은 이벤트를 즉시 2D로 재생하고, 늦게 들어온 시청자는 현재 시퀀스부터 보거나 처음부터 따라잡기(2배속)를 고른다.
- **리플레이(REPLAY)** — 종료 직후 전체 이벤트를 공개한다. 1배/2배속, 시퀀스 단위 건너뛰기, 득점 장면만 보기를 지원한다. 실시간을 놓친 시청자는 결과 스포일러 없이 리플레이부터 볼 수 있도록 목록에서 스코어를 기본으로 가린다.
- **방송 연동** — 스트리머는 17:00에 LIVE 화면을 방송에 띄워 시청자와 함께 관전한다. 16:30 라인업 공개, 16:50 예측 마감까지 방송 루틴 하나로 이어진다.
- **검증** — 종료 후 시드 원문을 공개해 `hash(seed) = seed_commit`을 누구나 확인할 수 있다(8.2).

### 6.4 컨디션 산식(초기 튜닝 값)

컨디션 C는 0~100. 유효 능력치는 E = 기본 능력치 × (0.60 + 0.40×C/100) × 부상 배율로 정의한다. 부상 배율은 건강할 때 1.0, 부상 상태에서 출전 강행 시 0.5이다. 부상 선수의 출전은 기본적으로 경고 및 감독 재확인을 요구한다.

v1.0: 경기 종료 후 출전 선수의 컨디션 감소량은 ΔC = 22 + round((100−STA)/10), 비출전/휴식 선수는 KST 일일 정산 때 +12, 출전 후 해당 일에는 추가 일일 회복을 지급하지 않는다. C는 항상 [0,100]으로 제한한다.

**[v1.1] 매일 경기에서는 v1.0 수식이 유지되지 않는다.** STA 40 선수는 출전마다 −28, 회복 0이라 100에서 시작해도 4일째 0에 닿는다. 등록 8명 중 5명이 고르게 로테이션해도 하루 평균 5/8×(−28) + 3/8×(+12) = −13으로 계속 떨어진다. 부상 확률(6.5)이 C에 따라 커지므로 리그 전체가 부상 상태로 수렴한다. 아래 값으로 바꾼다(2026-11-05 확정). 플레이테스트에서는 이 값을 기준선으로 미세 조정만 한다.

| 항목 | v1.0 | **[v1.1] 확정값** |
|---|---|---|
| 출전 시 감소 ΔC | 22 + round((100−STA)/10) | **12 + round((100−STA)/10)** (STA 40 → 18, STA 100 → 12) |
| 일일 정산 회복 — 비출전 | +12 | **+15** |
| 일일 정산 회복 — 출전 | 0 | **+5** |

확정값의 균형: STA 40 선수가 8명 중 5명 로테이션으로 뛰면 5/8×(−18+5) + 3/8×15 = 약 −2.5/일, STA 60이면 약 −1.3/일로 거의 유지된다. 반면 같은 선수를 매일 선발로 쓰면 −13/일로 4~5일마다 쉬게 해야 한다. 감독에게는 로테이션이라는 결정이 생기고, 선수에게는 체력(STA) 훈련 동기가 생긴다.

### 6.5 부상

경기 전 부상 확률 p_injury(C) = 0.005 + 0.04×(1−C/100)^2. 따라서 컨디션 100일 때 약 0.5%, 0일 때 약 4.5%이다. 이는 의학 통계가 아닌 게임 밸런스를 위한 임시 값이며 부상 빈도에 대한 플레이테스트가 필수다. 부상 발생 시 1~2경기 상태로 지정하고, 출전 강행 시 능력치 50% 추가 감쇠를 적용한다. **[v1.1] 경기가 매일 열리므로 "1~2경기"는 곧 1~2일이다. 부상 판정은 16:30 라인업 잠금 시점의 컨디션으로 한다.**

## 7. 승부예측·포인트

### 7.1 승부예측

도박성 운영 위험을 피하기 위해, 실제 재화·후원으로 매입할 수 없는 무상 예측 티켓만 사용한다. 포인트는 양도·환금·환불·현금성 상품 교환이 불가능하고 축구선수 직접 능력치 강화에 사용하지 않는다. 법률 검토 전에는 예측 참가를 위한 포인트 스테이킹도 구현하지 않는다.

**[v1.1] 매일 16:30에 라인업을 잠그고, 양 팀 전력 기준으로 공개 승·무·패 확률 p를 산출한다. 예측은 16:50(킥오프 10분 전)에 종료**하며, 한 계정당 경기당 한 번만 참여한다. 적중 시 보상은 R = min(50, round(10 / max(p, 0.10))) 포인트, 미적중 0 포인트로 한다. 확률과 보상 배수는 예측 개시 시 고정하고, 승부예측 선택이 경기 난수 또는 결과를 바꾸지 못하도록 한다. **[v1.1] 경기 결과는 예측 마감(16:50) 뒤인 17:00에 계산하므로, 예측 시점에는 서버에도 결과가 존재하지 않는다.**

*이 보상은 도박의 실제 배당률이 아니라 게임 내부 무상 보상 배수의 설계안이다. 실제 서비스 전 플랫폼 정책 및 적용 법령 검토 필요.*

### **[v1.2] 7.2 스토어와 거래소**

스토어는 **꾸미기 전용**이다. 능력치·컨디션·XP·돌파 증표·경기 결과에 영향을 주는 아이템은 팔지 않는다(1.1 공정성, 4.1). 화폐는 7장의 무상 포인트를 "성 포인트"로 통합해 쓴다 — 승부예측 적중, 일일 임무, 시즌 보상으로만 얻고, 현금으로 사거나 환전할 수 없다.

| 구분 | 내용 |
|---|---|
| 상품 — 선수 | 유니폼 스킨, 선수 카드 프레임, 골 셀러브레이션 연출, 응원 이모트, 닉네임 색 |
| 상품 — 구단(감독) | 엠블럼, 홈 킷, 경기장 배너, 라인업 공개 연출 |
| 등급 | Common / Rare / Epic (외형 차이만). 확률형 뽑기 없음 — 모든 상품은 고정가 직접 구매 |
| 구매 | 성 포인트 고정가. 구매 즉시 보관함 지급, 환불은 구매 후 24시간·미사용 시 |
| 유료 결제 | **도입하지 않는다.** 현금 구매가 필요하면 별도 정책 결정(결제·환불·청소년 보호·플랫폼 약관) 후 v2 범위 |

**거래소(유저 간 거래)** — 시청자끼리 꾸미기 아이템을 성 포인트로 사고판다. 포인트가 유저 사이를 오가는 순간 12장 보류 항목 "거래형 포인트"에 해당하므로, 아래 가드레일을 모두 걸고 **법률/정책 검토 통과 전에는 열지 않는다**.

| 가드레일 | 규칙 |
|---|---|
| 거래 대상 | 거래 가능 표시 아이템만. 시즌 한정·후원 보상·이벤트 보상은 계정 귀속(거래 불가) |
| 이용 자격 | 계정 생성 7일 경과 + 선수로 첫 경기 출전 이후. 스트리머 계정은 거래소 이용 불가 |
| 가격 범위 | 상점 기준가의 50%~300% |
| 수수료 | 판매가의 10%를 소각(포인트 회수 — 인플레이션 억제) |
| 횟수 | 판매 등록 1일 5건, 같은 아이템 재판매는 구매 후 7일 뒤 |
| 송금 | 거래소 밖 포인트 직접 송금·선물 없음 |
| 현금 거래 | 외부 현금 거래(RMT)는 약관 금지, 적발 시 아이템 회수·계정 제재 |

### 8.1 클라이언트 최적화

- 메인 사이트는 일반 HTML UI; 미니게임 진입 시에만 Unity 단일 빌드 로딩.
- 정적 2D 스프라이트와 UI 애니메이션 중심, 실시간 3D·후처리 금지.
- 목표 30FPS, 저성능 기기에서는 애니메이션 최소화; UX는 FPS에 의존하지 않도록 설계.
- Brotli 압축, Data Caching, 불필요한 패키지/셰이더 제거, 리소스 용량 측정.
- 성능 수용 기준(초기 목표): 압축 빌드 15MB 이하, 일반 광대역 환경 재방문 3초 이내 로드. 실제 기기에서 측정해 조정.
- Unity Web은 플랫폼/브라우저별 메모리 제약이 있으므로 Android Chrome, iOS Safari, 데스크톱 Chrome에서 최소 하나씩 성능 테스트.

### 8.2 서버 권한/악용 대응

- 모든 보상 지급은 서버 트랜잭션으로 확정; 이벤트 ID 고유키로 중복 지급 방지.
- 미니게임 시작 시 서버가 서명된 시도 토큰과 난수 시드를 발급; 종료 시 유효 시간·입력·결과를 검증.
- 경쟁성이 높은 게임은 점수 판정에 필요한 핵심 로직을 서버에서 재계산하고, 거짓 입력/매크로 패턴을 탐지.
- 감독 권한 RBAC, 선수 동의 기록, 트레이드 양방향 승인, 라인업 잠금 시각 서버 기록.
- **[v1.1] 마감 판정은 서버 시각만 쓴다. 16:30:00 이후 도착한 라인업 저장 요청과 16:50:00 이후 도착한 예측은 클라이언트 시각과 관계없이 거절한다.**
- **[v1.1] 경기 시드는 16:30에 해시만 커밋하고 종료 후 원문을 공개한다(commit-reveal). 운영자도 킥오프 전에 결과를 바꿀 수 없음을 사후에 검증할 수 있다.**
- **[v1.1] 관전 API는 `release_at`이 지난 이벤트만 응답한다. 결과 선노출로 예측을 악용하는 경로를 막는다.**

## 10. AI/ML 단계별 도입

| 단계 | 분석/모델 | 검증 지표 |
|---|---|---|
| 0단계: 데이터 QA | 중복 이벤트·비정상 점수 탐지, 주간 대시보드 | 수집 성공률, 이벤트 오류율 |
| 1단계: 행동 예측 | LightGBM/Logistic Regression 기반 재방문·훈련 선택 예측 | AUC/Log Loss, Calibration, D7 Retention |
| 2단계: 선수 성능 추정 | 포지션별 경기 기여도·예상 득점 기여 추정 | MAE, 순위 상관, 시뮬레이션 교차검증 |
| 3단계: 추천 | 훈련 미션/전술 추천 Contextual Bandit 실험 | 개선된 지표, 탐색 비용, IPS/DR OPE |
| 4단계: 최적화 | 감독 전략/개인 훈련의 Bi-level 또는 multi-agent 모델 | 전술 성과 + 공정성 + 참여 지속 |

연구 문제 예: 어떤 훈련 추천 정책이 선수들의 장기적인 경기 기여도와 D7 재방문율을 함께 개선하는가? 상위 문제는 추천/보상 정책 최적화, 하위 문제는 선수들의 훈련 선택·감독의 전술·경기 결과로 정식화한다. 실사용자에게 Nash equilibrium이나 인과성을 가정하지 않고 무작위 배정 또는 적절한 오프폴리시 평가로 검증한다.

### 10.1 핵심 제품 지표

- 퍼널: 로그인→선수 생성→팀 지원→첫 훈련 완료→첫 경기 출전.
- 활동: D1/D7/D30 Retention, 주간 활성 사용자, 비방송시간 참여 비율.
- **[v1.1] 경기일 루틴: 16:30 전 라인업 직접 제출률(자동 명단 비율), 예측 참여율, 17:00 실시간 관전 동시 접속, 리플레이 시청률.**
- 균형: 팀별 승률 분산, GK 포지션 기피율, 상위 10%와 중위값의 성장 격차 **[v1.1], 일일 컨디션 분포·부상 상태 선수 비율**.
- 공정성: 후원 유무별 성장 속도/승률 차이(활동 시간 등 교란 요인 통제).
- 성능: Unity 초기 로드 시간, p95 프레임 시간, 모바일 크래시율 **[v1.1], 17:00 정각 관전 API p95 응답 시간**.
- 데이터: 외부 이벤트 수집 누락/중복률, 확인 불가 시청시간 보상 비중.
